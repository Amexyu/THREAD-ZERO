# S1 审核意见（程序方 Claude → 素材会话）

日期：2026-11-16。对象：`Deliverables/ArtPack_v13/Character/starter/` 的 8 个部件、`parts.json`、`Review/S1/`。
结论：**部件本身合格，校验脚本全部通过**（8 个部件尺寸、锚点、透明边、关节重叠都对）。但用户用骨架驱动后觉得"歪、像弱智"，原因和下面几条修正有关，请在 S1 修订里一起处理。

## 原因：拼装位置没有写进交付物
`parts.json` 只有每个部件自己的锚点，**没有"站立时各部件摆在哪"**。程序方只能用自己的默认骨架去猜，结果身体前倾、腿并拢、手臂抬起，和 S0 的站姿不一样，看起来歪。
程序方已经临时按你 `Review/S1/assembly.png` 的待机拼装反推了一组数值，并写进 `parts.json` 的新字段 `rig`（见下），**请你核对并改成你拼装时用的真实数值**。

`rig` 字段约定（单位，相对于"躯干髋部锚点"，y 向上为负）：
```json
"rig": {"hip":[0,-24], "head":[2,-36], "pack":[-28,-24], "leg_near":[10,0], "leg_far":[-12,0]}
```
- `hip`：躯干锚点相对脚底中心的位置；
- `head`：头部锚点相对躯干锚点；`pack`：背包锚点相对躯干锚点；
- `leg_near`/`leg_far`：两条腿的锚点相对躯干锚点；
- 已有的 `shoulder`/`shoulderF` 同样相对躯干锚点。
**验收方式**：你用这些数值合成一张 `idle_rest.png`（站立、无武器、手臂自然下垂），程序方会用同一批数值渲染对比。

## 造型修正（相对 S0）
1. **头太大。** S0 里头约占整体高度 45%～52%；现在部件拼出来头约占 65%，显得头重脚轻、不像 S0。请把 `head` 缩小到约 80–88 单位宽，或把躯干和腿放长，让整体比例回到 S0。
2. **匕首太长。** 现在刃加柄 84 单位，约占身高 60%；S0 里匕首只有约身高的 25%。请缩到 **40–50 单位**。
3. **手臂与夹克同色，挥动时看不清。** 请给袖口或手套加一条青绿识别条，或让手臂比躯干略亮一档，保证摆臂时能看出来。
4. **后续部件必须与本套同一比例。** 以修订后的 S1 为基准，h1–h4、c1–c4、b1–b4 和其他武器都照这个比例画。

## 工具问题
你那台机器缺 Pillow 和 numpy，校验和渲染脚本跑不起来（`rig.log`、`validate_parts.log` 都是 ModuleNotFoundError）。请先装上：`pip install pillow numpy`。装不了的话，部件交付后程序方在另一台机器上跑，但你自检就缺一环，所以请尽量装。
