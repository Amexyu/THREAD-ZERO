## 1. 世界观与故事（先读，别编剧情）

### 1.1 已确认的设定（来自 `EquipmentSkills_MechanicalAscension_v12.md`）
主角身患疾病，为了生存进入封锁区回收机械零件，逐步修复、替换身体，最终实现机械飞升。战斗能力来自实际穿戴和安装的装备，角色不是天生会打。疾病名称、病因、结局细节**尚未确定**。

### 1.2 故事背景初版 = 上面 1.1 的内容（2026-11-16 用户确认）
用户确认：目前的"故事初版"就是 1.1 这一段背景方向，没有更长的剧本。具体病因、人物经历、结局**还没展开**。所以：

- 现在不要编造病名、组织名、人物名、剧情转折，也不要把任何剧情写进画面文字里；
- 标"需故事"的步骤（S7 的过场/标题、S8 机械化阶段与开场插画）**暂缓**，等用户补充故事后程序方再通知；
- 其余步骤（S0–S6）只依赖 1.1 和 1.3，可以直接开始。

### 1.3 现在就能依据的视觉隐喻（待用户确认，可随故事调整）
界面不再是"明亮的工业零件店"，而是**主角随身带着的维生与回收终端**。它同时是诊断仪、回收手册和零件台账：

- **维生 / 医疗**：生命体征曲线（ECG）、诊断表格线、输液管与线缆、胶布与缝线、病历编号铭牌。
- **封锁区 / 回收**：检疫封条、警戒条纹、零件托盘标签、编号铆钉、手写补丁、被划掉再重写的标记。
- **机械化**：已替换的部位用"零件规格标签"标注，未替换的用"人体"标注；界面上有一个"机械化进度"概念（见 §3.4），**只作为外观与叙事装饰，不影响数值**。
- **不要**：赛博霓虹、渐变发光、血腥、过多小细节、真实企业/品牌标识。

## 3. 界面：跟着世界观换皮

### 3.1 原则
- **布局不动。** 现有布局（左侧竖栏 128 逻辑像素，顶部路线节点，中间舞台，底部配装与控制）用户已认可，程序不会重排。要改的是**皮肤**。
- **逻辑画布 1600×900**，所有尺寸以此为基准；素材按 2 倍（3200×1800 等价）交付，程序缩放。
- 保留的色彩 token（程序里已在用）：地面 `#E8E9E4`、面板 `#F6F6F2`、墨色 `#121416`、深色块 `#1C1F22`、警戒橙 `#FF4A12`。品质色（灰 `#9CABB8` / 绿 `#6BD494` / 蓝 `#59A6FF` / 紫 `#BF80FF` / 金 `#FFC24D` / 红 `#FF4D5E`）不变，由程序绘制，不要烘焙进素材。
- 新增一个功能色：**维生青绿**（参考基准图里肩部识别条，建议 `#6FC3B2` 附近，低饱和），用于"生命、维生、人体部分"；橙色继续表示"警戒、封锁、操作"。
- 画风：平涂 + 一层硬边阴影 + 统一描边（逻辑 2 像素），与角色一致。

## 4. 角色素材：分层部件（Q 版比例）

沿用 v0.12 的做法：**每件装备只画 1～3 张单姿势部件图，动作由程序驱动**。规范与规则见 `Docs/给素材会话的任务清单_v0.12_分层部件.md` §0、§5～§10（画法硬规则、parts.json、验收流程不变）。以下是本轮**更新的内容**。

### 4.1 比例（用户要求更 Q）
- **头占整体高度约 50%～55%**；躯干是一个矮块；手臂和腿短而粗；手、脚相对偏大。
- 整个角色约 125 单位高（1 单位 = 4 像素 = 500 像素高，衣柜页会放这么大）。游戏战斗里它缩到约 210 像素，所以头部造型、武器、背包要用**大块面**。
- 占位参考：`Tools/RigPrototype/sample_parts/{A,B,C}`（已更新为新比例，通过校验）。占位只参考尺寸，不参考画风。
- 基准造型仍是《街头维生拾荒者》（`CharacterVisualBaseline_v12.md`）：灰色乱发、全遮脸的暗色护目面屏与呼吸器、石墨黑夹克、浅灰靴、肩部灰白护片、低饱和青绿识别条、小面积橙色标识。**请把它画成新比例的 Q 版**，不是照搬旧比例。

### 4.2 呼吸管与维生模块的处理（基准图遗留问题）
基准图里呼吸管连到背部维生模块，但背部装备要能自由更换。决定：
- 呼吸管画在 `head` 里，**只画到颈侧，进入领口**，不连到背部。
- 背部的维生模块外观画进 `b0 折叠回收背包`；其他背部装备不必有它。
- 这样换任意背部装备都不会出现悬空的管子。

### 4.3 装备 → 部件对应（共 20 件，来自 `Docs/EquipmentCatalog.md`，ID 与名称不改）

| 槽位 | ID | 名称 | 要画的部件 |
|---|---|---|---|
| 头部 | h0–h4 | 回收员兜帽 / 夜行面罩 / 信号护目镜 / 封闭式头盔 / 故障猫耳终端 | `head`，各 1 张 |
| 外套 | c0–c4 | 防雨勤务夹克 / 反光机能风衣 / 轻型装甲外套 / 逆流束带上衣 / 白噪研究长衣 | `torso` + `arm`，各 1 套 |
| 背部 | b0–b4 | 折叠回收背包 / 侦察天线模块 / 蓄电线圈模块 / 折叠防护翼 / 轻量推进背架 | `pack`，各 1 张 |
| 武器 | w0–w4 | 勤务短铳 / 霓虹切刃（匕首） / 线圈发射器 / 逆流手炮 / 重型破拆器 | `weapon`，各 1 张 |
| 素体 | — | 所有外套共用 | `legs` ×1（含靴子）；以后有机械化阶段变体 |

- 腿属于通用素体，不随外套更换。长款外套（c1 风衣、c4 长衣）的下摆先**画短到不盖过髋部**，下摆独立摆动的可选部件 `hem` 以后再说。
- `weapon_class`：w0、w2、w3 = `gun`；w1 = `dagger`；w4 = `heavy`（双手长重武器，程序侧先按 hammer 类动作处理）。
- 武器统一画成**从握把沿 +y（向下）画到尖端/枪口**，在 parts.json 里给 `tip`。枪类请额外给 `muzzle`（枪口点，同 `tip` 的写法即可）。
- 初始匕首 w1 的 18 姿势整帧样本保留为"技能演出"，普通攻击走分层。

### 4.4 骨架常量与尺寸表（取代 v0.12 §3/§4 的数字）
单位：1 单位 = 交付 PNG 的 4 像素。原点左上。

骨架挂点（程序侧固定，素材方只需让锚点对上）：
- 腿挂点：脚底中心上方 21 单位，左右 ±5；躯干髋点同在上方 21 单位。
- 头挂点：躯干局部 (2, −29)。背部件挂点：躯干局部 (−21, −20)。
- 肩挂点（默认）：近手 (11, −26)、远手 (−4, −26)，可在 parts.json 里用 `shoulder` / `shoulderF` 覆盖（重甲建议 (13, −29) / (−6, −29)）。
- 手点：手臂图底边**往上 11 单位**。

| 部件 | 尺寸范围（宽×高） | 锚点规则 |
|---|---|---|
| `head` | 88–110 × 76–96 | 底部中心：x≈宽/2(±8)，y∈[高−12, 高−4] |
| `torso` | 46–68 × 34–50 | 髋部：x≈宽/2(±6)，y∈[高−6, 高−1] |
| `arm` | 18–36 × 32–44 | 肩部：x≈宽/2(±4)，y∈[5, 13] |
| `legs` | 28–38 × 24–34 | 髋部：x∈[8, 16]，y∈[2, 7] |
| `pack` | 22–44 × 40–62 | 附着点：x∈[宽−10, 宽−2]，y∈[0.5高−4, 0.85高] |
| `weapon` | 10–40 × 60–140 | 握把：x≈宽/2(±5)，y∈[2, 45]，必须给 `tip` |

**以 `Tools/RigPrototype/validate_parts.py` 为准。** 它已按新尺寸更新。

### 4.5 动作（程序负责，素材方不用画）
待机呼吸蹦跳、走路（**纯蹦跳**：整体起落加落地挤压，腿只做很小的收放）、受击后仰与闪白、死亡倾倒淡出、攻击按武器类型（短刃连刺 / 枪械后坐射击 / 重武器举砸）。
**用户明确要求高稀有度武器各有独特动作与特效**，这条保留：到时每件高稀有度武器会单独提需求，现在不画。

### 4.6 机械化阶段（后期，需故事）
世界观要求主角逐步替换身体：初期是维生面罩 + 旧衣物 + 少量外置设备；中期是义肢、替换关节、接口；后期是稳定的机械机体。落到素材上就是 `legs`、`arm`（裸臂版本）等素体部件的阶段变体。**不要现在做**，等 §1.2 的故事和 Step 6 确认后再定。

```
Deliverables/ArtPack_v13/
  UI/                       kit.json + 切片 PNG
  Character/<套装名>/       parts.json + 部件 PNG
  Enemies/<id>/             idle.png, windup.png, wreck.png

  RECEIPT.md                本次回执
```
同时复制到 `ThreadZero/Assets/Resources/Art/V13/`。**不要覆盖 V07/V08/V12**，程序在缺图时会退回旧版本。

通用要求：
1. 透明 PNG，边缘干净，在浅底 `#E8E9E4` 与深底 `#1C1F22` 上都没有白边或灰底。
2. 不烘焙任何发光、辉光、体积光、渐变。
3. 命名用小写英文、数字、下划线；装备沿用现有稳定 ID。
4. 回执 `RECEIPT.md` 写清：交了什么、每个文件尺寸、锚点和切片数值，**量不出来的写 TBD，不要填估计值当实测**。
