# 夜间自动推进流程（2026-11-22 起）

用户的要求：**用户说去睡觉之后，到第二天回来找我之前**，由 Claude 按流程自己推进项目；手上的待办做完了就继续打磨，直到用户觉得这个项目可以为止。用户上线后看 `Docs/夜间报告/<日期>.md` 查收。

## 开始 / 结束

- 开始：用户说睡觉 / 下线（2026-11-22 那次从 01:07 开始）。
- 结束：用户回来发消息就停下，先汇报，再按用户的新指示做。
- 中途会话可能被压缩或结束：每做完一项就更新报告；用定时唤醒（send_later，每 45～60 分钟一次兜底）回到这个会话接着做。

## 每一轮

1. 读本文件和最新的夜间报告，确认上一项做到哪。
2. 按下面的优先级挑下一项，拆成能在一两个小时内验证完的小块。
3. 改代码 → 桥接编译（`compile`）→ 用桥接剧本实测（截图 / 连拍 GIF）→ 改了数值就跑数值模拟（`menu Thread Zero/数值测试/立即运行`）。
4. 自己先看截图 / GIF，不满意就继续改，满意了再写进报告。
5. 报告里写：做了什么、为什么、效果（GIF / 截图路径）、数值变化、还没解决的问题、需要用户拍板的事。

## 规则（和白天一样）

- **不提交、不推送**，改动留在工作区，等用户看完决定。
- 不覆盖 Gemini 原图；处理过的图另存（`_净.png`、`_朝左.png`），不要的移到 `_作废/`（不能删文件）。
- 不输入密码、不过验证码、不操控电脑屏幕（computer use）。
- Gemini 出图：2026-11-22 01:10 用户同意夜里直接用 Gemini 生成并下载**第四、五章的背景和怪**（其它出图先问）。照旧走 `Gemini/卡22`、`卡23` 的流程，原图不覆盖。
- 电脑要开着：Claude 桌面 App、Unity（本项目）、Chrome（插件 + Gemini 登录）都开着，Mac 不睡、屏幕不熄（用户跑 `caffeinate -dis`）。连不上就记进报告，先做不依赖它的部分。
- 改数值一定跑模拟，报告里写清楚前后对比。
- 需要用户拍板的设计取舍：先按最合理的做，报告里单列出来，方便用户推翻。
